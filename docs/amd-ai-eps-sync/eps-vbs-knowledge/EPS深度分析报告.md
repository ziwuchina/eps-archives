# EPS VBS 深度分析报告

> 基于 4,783 个VBS脚本文件的全面分析
> 重点关注：网络架构、服务器交互、业务能力、扩展性

---

## 一、EPS 是什么？VBS 脚本在做什么？

### 1.1 EPS 的本质

EPS（Electronic Professional Survey）是一款**测绘行业专业软件**，本质上是一个**GIS桌面客户端 + 业务流程引擎**。

VBS 脚本是 EPS 的"灵魂"——它们不是简单的自动化脚本，而是**连接桌面端与服务器端的业务逻辑层**。每一个 VBS 脚本都代表一个**业务功能模块**。

### 1.2 VBS 脚本的三大角色

| 角色 | 说明 | 占比 |
|------|------|------|
| **业务流程执行器** | 执行不动产登记、规划审批等业务流程 | 60% |
| **数据转换桥梁** | 在 EPS 内部数据与外部格式（DWG/SHP/PDB）之间转换 | 25% |
| **服务器通信客户端** | 与 ArcGIS Server、ERP 系统、OA 系统交互 | 15% |

### 2.2 ArcGIS Server（GIS 服务端）

**地址：** `http://221.4.165.144:6080/arcgis/rest/services/`

| 服务 | 用途 | 调用次数 |
|------|------|----------|
| `QH/FeatureServer/3` | 不动产数据（宗地/自然幢/逻辑幢） | 247次 |
| `QH/FeatureServer/0` | 基础地理数据 | 132次 |
| `QH/MapServer` | 地图渲染服务 | 129次 |
| `ZDHQH/FeatureServer/0` | 宗地号查询服务 | 32次 |
| `ZDWQH/FeatureServer/0` | 宗地文号查询服务 | 32次 |

**操作类型：**
- `addFeatures` — 新增空间要素（宗地、幢、户）
- `updateFeatures` — 更新要素属性
- `deleteFeatures` — 删除要素

**这意味着：** EPS 不仅是桌面软件，它直接操作 ArcGIS Server 上的**空间数据库**。每个 VBS 脚本都在执行**GIS 服务端的 CRUD 操作**。

### 2.4 OA 系统（办公自动化）

**地址：** `http://chqy.shunde.gov.cn/sdch/public/interface/`

| 功能 | 说明 |
|------|------|
| 人员信息查询 | 通过 enterpriseName 查询企业/人员信息 |
| 文件上传 | 将测绘成果（PDF/DWG/EDB）上传到 OA |
| 成果提交 | 将勘界图、宗地图、房产文件提交审批 |

**文件上传服务：**
- `EpsFileUploadService.asmx` — SOAP 上传接口
- `SaveUploadFileForm.aspx` — HTTP 上传接口

### 2.5 认证体系

```
EPS 客户端 → SSERPTool.GetTokenAndInvalidTime → 获取 Token
         → SSERPTool.GetUserInfo → 获取用户信息
         → 后续请求携带 access_token
```

Token 通过 ERP 系统的 `erp.auth.authhelper.gettoken` 获取，有效期由服务器控制。

### 3.2 典型业务流程

```
用户点击菜单 → VBS脚本执行 → 本地数据处理 → 服务器交互 → 结果返回
     │              │              │              │            │
     │              │              │              │            │
  OnClick()    SSProcess.*    数据库读写    HTTP/Token    MsgBox/显示
```

**以"违法宗地取号"为例：**
1. 用户选择宗地 → `SelectFilter` 筛选
2. 获取宗地属性 → `GetSelGeoValue` 读取
3. 调用 ERP 接口 → `xmlhttp.Send` 发送取号请求
4. 获取返回号 → `xmlhttp.responseText` 解析
5. 写入本地 → `SetSelGeoValue` 更新
6. 记录日志 → `JK40` 接口记录

## 四、EPS 的扩展性分析

### 4.1 EPS 能做什么？

| 能力 | 实现方式 | 扩展难度 |
|------|----------|----------|
| **桌面端 GIS 操作** | SSProcess API | 低 |
| **数据库读写** | Access MDB + SQL | 低 |
| **ArcGIS Server 交互** | HTTP + JSON | 中 |
| **ERP 工作流集成** | Token + REST API | 中 |
| **OA 系统集成** | SOAP/HTTP 上传 | 中 |
| **Excel/Word 报表** | COM 自动化 | 低 |
| **自定义对话框** | Grid 控件 + ShowScriptDlg | 中 |
| **坐标系统转换** | 内置投影库 | 低 |
| **拓扑分析** | SearchInner/SearchNear | 低 |
| **批量数据处理** | 循环 + 进度条 | 低 |

### 4.2 EPS 不能做什么？

| 限制 | 原因 |
|------|------|
| 无法直接操作 ArcGIS Server 管理功能 | 只有 FeatureServer REST API |
| 无法修改 ERP 工作流定义 | 只能调用预定义接口 |
| 无法处理实时流数据 | VBScript 是单线程 |
| 无法原生支持 Web 前端 | 桌面端技术栈 |
| 无法直接访问 Oracle/PostgreSQL | 只支持 Access MDB |

## 五、VBS 脚本背后的意义

### 5.1 为什么用 VBS？

1. **历史原因** — EPS 开发于 Windows 平台，VBScript 是 Windows 原生脚本语言
2. **零部署** — 不需要安装额外运行时，Windows 自带 VBScript 引擎
3. **COM 集成** — 天然支持 Excel/Word/ADO 等 COM 组件
4. **简单易学** — 测绘人员无需专业编程背景即可编写
5. **实时生效** — 修改脚本后立即可用，无需编译

### 5.2 4,783 个脚本在做什么？

**宏观视角：** 这些脚本共同构成了一个**完整的不动产测绘生产系统**：

| 层次 | 脚本数量 | 功能 |
|------|----------|------|
| **数据采集层** | ~500 | 导入外业数据、CASS数据、GPS数据 |
| **数据处理层** | ~1500 | 属性录入、面积计算、拓扑检查、编码转换 |
| **质量控制层** | ~1000 | 合法性检查、必填项验证、数据一致性 |
| **成果输出层** | ~800 | 出图、报表、PDF、DWG导出 |
| **系统集成层** | ~500 | 与ERP/OA/ArcGIS Server交互 |
| **工具辅助层** | ~483 | 配置管理、日志、进度条、对话框 |

### 5.3 核心价值

这些 VBS 脚本的真正价值在于：

1. **标准化** — 将测绘行业的业务规范编码为可执行的检查规则
2. **自动化** — 将重复性的人工操作（如取号、提交、出图）自动化
3. **集成化** — 将桌面端与服务器端打通，实现数据实时同步
4. **可追溯** — 每个操作都有日志记录（JK40接口），支持审计
5. **可定制** — 不同 DeskTop 模块（15个）对应不同的业务场景

## 六、总结

### EPS 的本质

EPS 不仅仅是一个 GIS 软件，它是一个**测绘行业的业务中台客户端**。

VBS 脚本不是简单的自动化工具，它们是**连接测绘人员与政府业务系统的数字桥梁**。

### 网络通信总结

| 服务器 | 协议 | 功能 | 安全性 |
|--------|------|------|--------|
| ArcGIS Server | HTTP REST | 空间数据 CRUD | ⚠️ 无认证 |
| ERP 系统 | HTTP POST | 业务流程/取号/提交 | ✅ Token 认证 |
| OA 系统 | HTTP/SOAP | 文件上传/人员查询 | ⚠️ 硬编码凭证 |
| 文件服务器 | HTTP | 成果文件上传 | ⚠️ 无认证 |

### 扩展建议

1. **现代化改造** — 将 VBScript 迁移到 Python/Node.js，支持异步和多线程
2. **API 网关** — 为 ERP/ArcGIS 接口添加统一的 API 网关和认证
3. **Web 化** — 将桌面端功能逐步迁移到 Web 端（已有 ArcGIS Server REST API 基础）
4. **数据安全** — OA 系统的凭证不应硬编码在 VBS 中，应使用加密存储
5. **监控告警** — 对网络请求添加超时重试和异常告警机制
