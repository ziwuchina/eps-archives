## 一、项目概述

### 1.1 是什么

顺德宗地号定位脚本是 EPS 测绘平台（顺德基础测绘专版）的右键菜单扩展，功能为：**输入宗地号 → 自动查询土地信息并绘制地块边界**。

### 1.2 工作流程

```
用户在 EPS 中右键 → 选"宗地号定位"菜单
  ↓
VBS 弹出输入框 → 输入宗地号（如 199017-008）
  ↓
VBS 调用 zongdi.bat → 启动 Python 脚本
  ↓
Python 调用天地图 API（通过 RSA+3DES 加密代理）
  ├─ 查询宗地边界坐标（CGCS2000 经纬度）
  ├─ 经纬度 → 投影坐标（WebService 转换）
  └─ 查询坐落地址（ERP 接口）
  ↓
结果写入 _zongdi_result.txt
  ↓
VBS 读取结果 → EPS 绘图（面 + 中心点 + DJH/BBH/ZL 注记）
```

## 二、v4 → v5 迁移过程

### 2.1 迁移动机

v4 项目存在一个核心问题：`geo_to_proj` 函数依赖内网 WebService（`http://19.200.42.50/NServiceAdapter/WebService`），该服务通过 RSA + 3DES 双层加密代理访问。一旦内网不可达，整个脚本失效，无法离线使用。

目标：**用本地 `pyproj` 库替代 WebService，实现坐标投影的本地计算，消除网络依赖。**

### 2.2 尝试过程（按时间线）

#### 阶段一：标准 EPSG 投影尝试 —— 失败

宗地查询返回的是 CGCS2000 经纬度（如 `113.0682238, 22.9543294`），期望投影输出约为 `(707000, 2539481)`。

| 测试 | 参数 | X 输出 | 偏差 |
|------|------|--------|------|
| EPSG:4545 | CGCS2000 / 3°GK CM=111°E | 1,020,257 | **313 km** |
| EPSG:4546 | CGCS2000 / 3°GK CM=114°E | 712,143 | **5.1 km** |
| EPSG:4526 | XIAN80 / 3°GK CM=111°E | 38,404,437 | **3.7 万 km** |

**发现**：没有任何标准 EPSG 代码能匹配 WebService 输出。EPSG:4546 最小也有 5km 偏差，远超出可接受范围。

#### 阶段二：椭球切换与 GCJ-02 纠偏 —— 失败

| 尝试 | 效果 |
|------|------|
| 切换椭球（WGS84 / Krassovsky / IAG75 / Clarke） | 偏差变化仅 3-4 米，不是根因 |
| GCJ-02 → WGS84 纠偏后投影 | 纠偏量 ~242m（经度）+ ~288m（纬度），投影后仍有 4.9km 偏差 |

**发现**：椭球选择和坐标加密偏移都不是根因。问题在于顺德 WebService 使用的不是标准高斯-克吕格投影。

#### 阶段三：双点仿射拟合 —— 局部通过，全局失败

以 v4 WebService 输出的两个已知点为基准，反推拟合投影参数：

```
PROJ 参数：
+proj=tmerc +lat_0=0 +lon_0=111.05015723632815
+k=1 +x_0=500000 +y_0=-1420.4772906345315
+ellps=GRS80 +units=m +no_defs
```

拟合点精度：**< 0.3mm**（极高）。

但用于实际宗地 `199017-008` 绘图时，12 个边界点偏差如下：

| 点 | dx (m) | dy (m) |
|----|--------|--------|
| J1 | +0.006 | +0.066 |
| J2 | +0.012 | +0.072 |
| J3 | +0.097 | -0.039 |
| J4 | +0.097 | -0.039 |
| J5 | +0.037 | +0.058 |
| J6 | +0.041 | +0.063 |
| J7 | +0.040 | +0.118 |
| J8 | +0.039 | +0.118 |
| J9 | +0.031 | +0.132 |
| J10 | -0.088 | +0.173 |
| J11 | -0.106 | +0.154 |

**最大偏差达 0.17m**，在 EPS 图形中肉眼可见偏移，**不可接受**。

**失败根因**：

双点仿射拟合本质是**局部线性近似**。2 个点只能确定平移 + 旋转 + 缩放，无法还原 WebService 内部可能使用的：
- 七参数基准转换（3 平移 + 3 旋转 + 1 缩放）
- 地方独立坐标系自定义参数
- 格网改正文件（NTv2 / NADCON 等）

这就像用两枚钉子固定一张橡皮膜——钉子处纹丝不动，但膜上其他位置会漂移。

#### 阶段四：API 逆向 —— 寻找绕过转换的可能

既然本地投影行不通，尝试从 API 下手——看宗地查询接口是否能直接返回投影坐标。

| 尝试方向 | 详情 | 结果 |
|----------|------|------|
| 原始返回分析 | 检查 `data.coords`、`geometry` 所有字段 | `coords` 始终 `null`，无投影坐标 |
| 切换 format | geojson / json / wkt / wkb | 仅 `esrijson` 有效 |
| 切换 action | query / search / get | 全部返回 `success=false` |
| 注入投影参数 | `outSR=4546` / `proj=1` / `returnProjected=true` / `outputCoord=xy` | 全部被忽略 |
| 探测其他端点 | SDWS_PARCEL_QUERY、SDWS_MAP_QUERY 等 | 全部 `401 Not Authorized` |
| 绕过加密代理 | HTTP 直连 `19.200.42.50` | 连接超时 |
| ArcGIS REST 接口 | `/arcgis/rest/services` | 不存在 |

**最终结论：宗地查询 API 只返回经纬度，不存在任何隐藏的投影坐标字段。要获得投影坐标，`geo_to_proj` WebService 是唯一路径。**

### 2.3 最终方案：回退 WebService

放弃本地 pyproj 投影，在 v5 的 `shunde_parcel_tool.py` 中直接内联 `geo_to_proj` 函数，完整保留 WebService 调用链路：

```python
def geo_to_proj(points):
    """CGCS2000 经纬度 → 投影坐标，调用 SDWS_TRANSCOORD_G2KGFS2K"""
    ws_url = (
        f"{WS_BASE}/SDWS_TRANSCOORD_G2KGFS2K/{WS_TOKEN}"
        f"?reserse=0&mode=1&points="
        + json.dumps([{"x": p[0], "y": p[1]} for p in points])
    )
    return _call_api(ws_url, exist_geo="0")
```

## 四、复盘与发现

### 4.1 核心发现

**发现一：顺德 WebService 使用的是非标自定义投影坐标系**

这是整个迁移失败的根本原因。WebService `SDWS_TRANSCOORD_G2KGFS2K` 内部的坐标变换不是标准的高斯-克吕格 3° 带投影，很可能涉及：

- 地方独立坐标系的七参数基准转换
- 顺德本地的格网改正数据
- 非公开的自定义投影参数

标准 EPSG 代码（4545、4546）和双点拟合都无法复现，偏差量级（5km + 0.17m）表明确实存在非线性的坐标变换。

**发现二：天地图宗地查询接口设计上只提供经纬度**

经多维度逆向验证（format 切换、action 切换、投影参数注入、端点探测），API 返回的 `geometry.rings` 和 `center` 仅含经纬度，`coords` 字段始终为 `null`。这不是隐藏，而是接口设计本身就不产出投影坐标。

**发现三：加密代理体系限制了直接服务发现**

所有 WebService 调用必须通过 `tianditu.shunde.gov.cn/webapi/api/External/PostLandInfo` 加密代理中转。这意味着：
- 无法直接访问 WSDL 获取服务列表
- 无法探测未授权端点（受 RSA 加密保护）
- 可用的服务端点是硬编码在白名单中的

**发现四：pyproj 在测绘精度场景下需要完整参数**

pyproj 本身功能完整，但精度取决于输入参数的完整程度。对于标准 EPSG 投影（如 CGCS2000 → 高斯-克吕格），pyproj 精度与官方实现一致。本次失败不是因为 pyproj 精度不足，而是因为顺德 WebService 的投影参数无法从外部获取。

### 4.2 经验教训

| 教训 | 说明 |
|------|------|
| **先验证再开发** | 如果一开始就用 `geo_to_proj` 的输入/输出做 EPSG 反查，10 分钟就能发现标准投影不匹配，避免 pyproj + 双点拟合的 3 小时弯路 |
| **拟合有边界** | 双点仿射拟合在拟合点附近精度极高（<0.3mm），但推广到其他点时误差快速放大。测绘场景需要完整投影参数，局部拟合不可行 |
| **API 逆向要系统化** | 按 format → action → 参数 → 端点 → 直连的顺序逐一排除，比随机尝试高效 |
| **网络依赖不是一定坏** | 虽然目标未达成（消除网络依赖），但确认了依赖的必要性，避免了未来的无效投入 |

### 4.3 未来可行的探索方向

| 方向 | 可能性 | 说明 |
|------|--------|------|
| 联系天地图顺德运维 | 中 | 索取投影参数定义或 API 文档，获取七参数等 |
| 增加采样密度拟合 | 低 | 从 2 点扩到 100+ 点做多项式/薄板样条拟合，但精度上限不确定 |

| 双路径 Fallback | 中 | WebService 不可达时降级使用双点拟合（标注 ±0.2m 误差） |
