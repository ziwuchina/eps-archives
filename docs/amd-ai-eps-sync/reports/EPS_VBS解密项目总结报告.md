## 三、解密方案

### 3.1 加密体系分析

- 加密体系统一使用头部标识 `@1234567890-`（13 字节）
- 每个 VBS 文件的加密密钥由其父模板 VBS 决定，密钥标识为 `720012004600`、`720023005100` 等
- 同一密钥 ID 的所有文件共享同一密钥流
- 密钥长度固定，大文件尾部无法解密
- `7200050047` 模式的 7 个文件无对应密钥，无法解密

### 3.2 三步解密流程

**第一步：基线解密**
- 使用原始 key_720012004600.bin（46 KB）和 key_720023005100.bin（925 KB）
- 对源目录所有 VBS 逐文件解密

**第二步：密钥扩充**
- 从 EPS2020 顺德基础地理测绘专版G（`D:\EPS2020顺德基础地理测绘专版G\DeskTop`，含 4,545 个明文脚本）中匹配同名文件
- 利用明文 XOR 密文 = 密钥流的原理扩充密钥
- key_720012004600.bin：46 KB → 2,128 KB（+45 倍）
- key_720023005100.bin：925 KB（含 23.2% 零值区域，300K 后基本为空白）

**第三步：替换密钥重跑**
- 使用扩充后的密钥重新解密全部文件

## 六、发现与复盘

### 6.1 关键发现

1. **加密体系统一但密钥分散**：所有 EPS 版本均使用相同的 `@1234567890-` 加密头 + ScriptCryptor XOR 流密码方案，但不同版本、不同模板的 VBS 使用不同密钥，密钥由父模板决定，无法通用。

2. **XOR 流密码的脆弱性**：只要有同名明文 VBS 文件即可通过 XOR 运算提取密钥流。本项目中通过 EPS2020 顺德基础地理测绘专版G 中的 4,545 个明文脚本匹配同名文件，成功将密钥从 46 KB 扩充到 2,128 KB。

3. **版本定制化程度高**：本目标版本（EPS2022 顺德联合测绘专版）脚本高度定制，与其他 18 个 EPS 版本无任何内容重叠，内容指纹暴搜、PRNG 逆向（RC4 / XorShift128 / LCG）均失败。

4. **密钥周期问题**：解密工具不复用密钥周期，超长文件（如最大文件 4,091,354 字节的"联合测绘+地形输出.vbs"）尾部字节无法解密。这是 key_720023005100 中 300K 之后零值区域的直接后果。

5. **种子密钥不可直接使用**：用户提供的 32 字节种子密钥（`7A52334557037F0C...`）与真实密钥流前缀不匹配，它是 ScriptCryptor PRNG 的种子参数，而非循环 XOR 密钥。

### 6.2 技术复盘

| 方案 | 结果 | 原因 |
|------|------|------|
| 基线解密（原始密钥） | 部分成功 | 原始密钥仅 46 KB，覆盖不足 |
| 同名匹配扩充密钥 | **成功** | EPS2020 顺德基础测绘版提供大量明文源 |
| 跨版本同名匹配（18个版本） | 失败 | 脚本高度定制，无同名文件 |
| 内容指纹暴搜 | 失败 | 版本间无内容重叠 |
| PRNG 逆推种子 | 失败 | 算法伪随机性足够，无法暴力破解 |
| 最终替换密钥重跑 | **99.9% 解密率** | 7,117/7,124 完全解密 |

### 6.3 经验总结

- **同名明文是最佳突破口**：在无法逆向 PRNG 的情况下，寻找同名明文 VBS 是唯一有效的密钥提取方式。同一测绘院的兄弟版本是最佳来源。
- **不要依赖单版本**：EPS 各版本间差异极大，跨版本匹配几乎不可能。需要针对每个目标版本寻找其对应的明文版本。
- **密钥扩充后检查零值区域**：扩充后密钥中仍存在零值区域，对应大文件尾部无法解密。后续改进可在解密工具中加入密钥周期复用逻辑。
- **7 个无法解密的文件**：均属于 `7200050047` 模式，该密钥在所有已知明文版本中均不存在，无法通过现有手段解密。
