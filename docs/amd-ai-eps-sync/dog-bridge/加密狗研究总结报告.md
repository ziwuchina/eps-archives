## 一、结论速览

| 问题 | 答案 |
|---|---|
| **加密到底在哪?** | 坐标 double 数值本身,做"缩放(cos)+平移"数学变换,非密码学加密 |
| **软件变没变?** | 没变。变的是从加密狗读出的 4 个参数(2 平移 + 2 旋转角) |
| **TransEdbEF 怎么做到?** | 两套参数**写死在 exe 里**,读坐标 → 用源参数解密 → 用目标参数加密 → 写回,不依赖狗 |
| **顺德狗能烧成佛山狗吗?** | **不能**。KeyMaker 只能写 ziwuchina 厂商区,佛山 EPS 读另一厂商区 |
| **最优方案** | 继续用 TransEdbEF;或基于已破解公式自写批量转换脚本 |

## 二、加密机制(核心发现)

### 2.1 EDB 文件本质
- EDB 是 **Microsoft Jet/Access 数据库**(文件头为 `Standard Jet DB`)
- 坐标以 8 字节 double 存储,散落在 Jet 数据页的记录中

### 2.2 坐标加密公式
```
保存(加密):  X' = X · cos(θ1) + 平移1
              Y' = Y · cos(θ2) + 平移2

打开(解密):  X = (X' − 平移1) / cos(θ1)
              Y = (Y' − 平移2) / cos(θ2)
```
- 加密狗的作用:仅提供 `平移1/平移2/θ1/θ2` 这 4 个数
- 因子在 EPS 启动时由 `SSCore32.dll` 的 `InitAuthorization` 从狗读取,存入全局对象 `0x101bac28` 的 `+0xa0`~`+0xc8` 偏移

### 2.3 两套参数(已确认)

| 版本 | 平移1 | 平移2 | 旋转θ1 | 旋转θ2 | 参数来源 |
|---|---|---|---|---|---|
| **顺德** | 18 | 60 | 11° | 9° | KeyMaker 读狗显示 |
| **佛山** | 45763 | 12846 | 10° | 20° | TransEdbEF 内码解码 |

- 佛山参数 `0x40e65860=45763`、`0x40c91700=12846` 已在 TransEdbEF.exe 二进制中确认
- 顺德参数与 KeyMaker 界面显示完全一致

## 三、TransEdbEF 原理(反汇编证据)

### 3.1 关键事实
- TransEdbEF.exe 仅 49KB,只依赖 `SSCore32.dll`
- **不调用** `EncryptCoord`、**不调用** HASP/Sentinel API、不依赖加密狗
- 导入的核心函数:`CByteStack`(字节流序列化)、`DegToRadian`(角度转弧度)

### 3.2 转换流程(0x403b40 / 0x403c80 / 0x403d60 三函数)
```
① CByteStack 解析源 EDB → RestoreD 逐个读 double 坐标
② 用源版本参数解密还原真实坐标:(X−18)/cos(11°)
③ 用目标版本参数重新加密:X·cos(10°)+45763
④ Store 写回 → 生成目标版本 EDB
```
- 参数硬编码于 `0x403ab0` 函数的两个分支(标志=0 → 顺德参数;标志≠0 → 佛山参数)
- 常量 `1e-5 / 1e-7 / 5e-6 / 5e-8 / 1.0 / 1e-6` 用于角度精度处理

### 3.3 验证(用户同源数据)
对比 `顺德版数据.edb` 与 `佛山版数据.edb`:
- 大小完全一致(31,531,008 字节),文件头相同
- 差异仅 1,038,900 字节(3.3%),集中在坐标区
- 同偏移坐标差 ≈ **45747**(= 45763 − 18 = 45745,含 cos 角度微调)✓

## 四、为什么"烧狗"路线失败

```
顺德狗(ziwuchina 厂商区)     佛山狗(另一家厂商区)
        │                           │
  KeyMaker_ziwuchina          佛山厂商的写狗工具(无)
        │                           │
  只能烧 ziwuchina 区           只能烧佛山厂商区
```

1. **佛山狗在 KeyMaker 上显示"无内容"** → KeyMaker 的 SSK(50000-50700 / 50000-59999)不认识佛山狗的厂商区
2. 即使把佛山参数(45763/12846/10/20)烧进顺德狗的 ziwuchina 区,**佛山 EPS 读的是另一个厂商区**,读不到 → 依旧打不开佛山数据(用户实测验证)
3. 结论:工具层面无解,TransEdbEF 是官方设计的数据互通方案
