> 项目时间:2026-08-19 至 2026-09-19
> 项目性质:加密狗授权数据的版本互通研究 + 自动化工具链开发(官方厂商已倒闭,无技术支持,一切研究基于自持正版狗与官方工具)
> 核心成果:EDB 加密机制 100% 破解,EDBConvert 转换器与 TransEdbEF 输出逐点一致(68,171 点 0 误差),并完整嵌入 EPS 打开/保存/上传全流程

## 一、项目背景与业务场景

### 1.1 业务困境

用户是测绘公司,使用 EPS 软件进行房产测绘生产。手上有两条**正版加密狗**:

| 狗 | 版本 | 用途 |
|---|---|---|
| 佛山狗 | 佛山版 | 读取部门下发的佛山版 EDB 数据 |
| 顺德狗 | 顺德版 | 日常绘制生产 |

**核心矛盾**:两个版本生产的 EDB 数据**互不通用**——
- 顺德狗只能打开顺德版数据,打开佛山版会报"加密狗注册"错误
- 佛山狗只能打开佛山版数据
- 官方提供了 `TransEdbEF.exe` 做两个版本的数据转换,但每次都要手工操作,非常麻烦

**业务流程**:
```
申请区域佛山EDB地形库 → 顺德狗打开(需转顺德版)→ 测绘生产更新 → 上传回佛山部门(需转回佛山版)
```

### 1.2 用户目标

1. 搞清 TransEdbEF 到底做了什么、加密机制是什么
2. 实现**打开时自动转顺德版**(顺德狗能读),**保存/上传时自动转佛山版**(部门能收)
3. 全程无人值守、文件名不变(不破坏生产链路)
4. 工具可整体迁移到其他电脑

## 二、加密狗机制解密(第一阶段)

### 2.1 官方文档揭示的机制

从 `F:\qsxx\ziwuchina\ziwuchina\使用说明.txt`(官方文档)直接获得核心线索:

> **EDB 数据的"加密"不是密码学加密,而是坐标值的数学变换**(平移 + 旋转)

| 要素 | 内容 |
|---|---|
| 因子1、2 | 平移量(官方建议 <100) |
| 因子3、4 | 旋转量(官方建议 0-30 度) |
| 数据加密方式 | 坐标值做"平移 + 旋转"数学变换 |
| 锁定规则 | 烧录了因子的锁生产的数据,不能被未烧录参数的锁打开 |

### 2.2 两套因子(关键数据)

| 版本 | 平移1 (X) | 平移2 (Y) | 旋转θ1 | 旋转θ2 |
|---|---|---|---|---|
| **顺德** | 18 | 60 | 11° | 9° |
| **佛山** | 45763 | 12846 | 10° | 20° |

- 顺德参数与 KeyMaker 显示一致(18/60/11/9)
- 佛山参数从 TransEdbEF 二进制中直接解出
- 验证:`0.984808 = cos(10°)` 出现在二进制常量区,坐实旋转角度解读

### 2.3 写狗工具与厂商区(为何"把顺德狗写成佛山狗"不可行)

- 用户手上有官方写狗工具 `KeyMaker_ziwuchina.exe`(口令 `sd11hasphl`)和 `.ssk` 文件(Sentinel 开发商密钥)
- **实测结论:佛山狗在 KeyMaker 中显示"空"(不识别)** → 佛山狗不是 ziwuchina 厂商的,是另一家厂商的狗
- KeyMaker 只能写 ziwuchina 厂商区,佛山 EPS 读另一厂商区 → **烧狗路线在工具层面走不通**
- 结论:TransEdbEF(或等价的自主转换器)才是唯一可靠方案

### 2.4 加密标记

- 顺德版数据内 `IniInfoTB` 表的 `EncryptCoordMark` = `1ds1`
- 佛山版 = `1sf0`
- 标记格式 = `1` + 城市缩写倒序 + 版本号

## 三、TransEdbEF 逆向破解(第二阶段,核心攻坚)

### 3.1 技术侦察

| 对象 | 发现 |
|---|---|
| TransEdbEF.exe | 仅 49KB,只导入 EPS 自家 SSCore32.dll,不走标准 Sentinel API |
| SSCore32.dll | 2137 个导出函数,内部调用完整 HASP API(hasp_login/read/encrypt/decrypt) |
| 关键函数 | `EncryptCoord`、`InitAuthorization`、`TransDateTime2INT` 等 |

### 3.2 静态反汇编关键结论

- 加密坐标核心:全局对象 `0x101bac28` + 偏移 `+0xa0`~`+0xc8`(6 个 double 因子)
- 因子来自狗内"种子结构"(56 字节),启动时 `InitAuthorization` 读入内存
- 顺德/佛山两套参数硬编码在 TransEdbEF 内(`0x403ab0` 两个分支)
- TransEdbEF **不调用 EncryptCoord**,只用 `CByteStack`(字节流)+ `DegToRadian`(角度转弧度)自行实现

### 3.3 终极公式(100% 复刻,68,171 点 0 误差)

```
B = (N × ID + Tmod) % 1000
Tmod = (616 + 月×576 + 日×384 + 时×256 + 分) % 1000     ← 要素 CreateTime 驱动

顺德 → 佛山 (S2F):
  X_fs = X_sd + 45745 + B × ((i+1)%100) × (cos10° − cos11°)
  Y_fs = Y_sd + 12786 + B × ((i+1)%100) × (cos20° − cos9°)

佛山 → 顺德 (F2S):
  X_sd = X_fs − 45745 − B × ((i+1)%100) × (cos10° − cos11°)
  Y_sd = Y_fs − 12786 − B × ((i+1)%100) × (cos20° − cos9°)

45745 = 45763 − 18   (佛山平移 − 顺德平移)
12786 = 12846 − 60
```

### 3.4 破解关键路径(复盘:为什么之前失败了)

| 阶段 | 发现 | 意义 |
|---|---|---|
| 差分回归 | `ΔXf = a·ΔXs + c` → **a=1.00000000(无缩放!)** | 颠覆"除 cos 乘 cos"假设 |
| 斜率比值 | cX/cY = -0.06627 = (cos10−cos11)/(cos20−cos9) | 锁定 100 点周期项结构 |
| B 的 ID 依赖 | 反汇编发现 `imul` 用的是 **ID** 而非 0/1 标志 | 参数映射反了 |
| Tmod 时间驱动 | ID 2400 偏差 +1 → 其 CreateTime=11:48:05(分钟48)≠383(分钟47) | B 随要素 CreateTime 变化 |
| 地址项消除 | TransDateTime2INT 的栈地址%1000 对 8 个解恒 ≡616 | Tmod 是纯函数,与地址无关 |

### 3.5 数据级验证(同源双版本对比)

用户提供同源两份数据(顺德版/佛山版,同由 TransEdbEF 转出):
- 文件大小完全一致(31,531,008 字节),头部完全相同(`Standard Jet DB` = Microsoft Jet 数据库)
- 差异仅 3.3%,集中在坐标 double 区
- 同一位置坐标:佛山 − 顺德 ≈ 45747 恒定(符合 45763−18=45745 理论值)
- **证明:加密只活在坐标数值里,文件结构完全没动**

## 四、EDB 文件格式分析(转换器的数据基础)

### 4.1 EDB = 标准 Jet 数据库

- 文件头 `Standard Jet DB` → **Microsoft Access/Jet 格式**
- 可用 `pyodbc + Microsoft Access Driver (*.mdb, *.accdb)` 直接读写
- 196 张表,坐标在 4 张图形表的 `Graphics` BLOB 字段

### 4.2 坐标 BLOB 结构(完全摸清)

```
GeoPointTB:  1字节标志 + N 点 × (X,Y double) ...(简)
GeoLineTB:   2字节点数 + 1字节类型 + N×(X,Y double,16字节) + 14字节尾部
GeoAreaTB:   同线,但面要素结构类似
MarkNoteTB:  注记
包围盒 MinX/MinY/MaxX/MaxY 是明文(TransEdbEF 也不改)
```

### 4.3 转换器只动的部分

| 动 | 不动 |
|---|---|
| 4 张图形表 Graphics BLOB 中的坐标 double | 包围盒(TransEdbEF 不改) |
| `IniInfoTB` 的 EncryptCoordMark(1ds1↔1sf0) | CreateTime(参与 B 计算,改了反而错) |
| | 其他属性/编码/图层字段 |

## 六、EPS 内部集成(第四阶段)

### 6.1 EPS 二次开发机制(官方 API)

- EPS 支持 VBS 脚本钩子:位于 `DeskTop\<方案>\Script\系统消息\`
- 关键 API(从 `EpsScript.chm` 确认):
  - `SSProcess.SelectFileName` 文件选择框
  - `SSProcess.OpenDatabase` 打开 EDB
  - `SSProcess.CloseDatabase` 关闭当前工程
  - `SSProcess.GetProjectFileName` 获取当前工程路径
- 菜单钩子:`BdcProjectMan_GetScriptMenuItem.vbs`(菜单名→脚本映射)+ `GetScriptMenuCmds.vbs`(菜单显示)

### 6.2 三个功能入口

| 入口 | 文件 | 功能 |
|---|---|---|
| **打开佛山数据** | `打开佛山版EDB.vbs` | 选佛山EDB → 备份.bak → F2S → 同名替换 → EPS打开 |
| **保存到佛山数据** | `保存到佛山数据.vbs` | 取当前工程 → 安全副本 → 关工程 → S2F → 同名替换 |
| **上传自动转换** | 4 个上传脚本的 FileCopy | 复制副本时自动 S2F,上传佛山版 |

### 6.3 关键业务逻辑(打开/保存成对闭环)

```
申请到佛山 0820.edb
  → 点「打开佛山」: 0820.edb.bak (佛山原版留底) + 0820.edb (转顺德版,打开)
  → 顺德狗生产绘制 (EPS 实时自动保存, 0820.edb = 顺德版最新)
  → 点「保存佛山」: 关工程 → 副本S2F → 同名覆盖 0820.edb (佛山版, 可交回)
  → 下次申请新数据, 循环 (.bak 同名覆盖, 只留最新佛山原版)
```

**核心安全原则**:
- 打开时:先备份 .bak,转换成功才替换,失败原文件不动
- 保存时:先复制安全副本 .sd_tmp,关闭工程释放占用,再同名替换,失败从副本恢复并重开
- 上传时:只操作 FileCopy 副本,打开中的工程文件零影响

### 6.4 工具条按钮注入(bar 文件)

- bar 文件是 **BCG 序列化二进制**(GBK 编码 + 长度前缀 + 按钮体)
- 按钮格式:`前序 3a80 + ID + 00000000 + ffffffff + 长度 + 名称 + 命令`
- 命令格式:`$epsscript,.\系统消息\打开佛山版EDB.vbs`
- 已注入按钮:「打开佛山」(ID 0xEB92)+「保存佛山」(ID 0xEB93),图标 0x3b
- **重大教训:改 bar 时 EPS 进程必须关闭!** 否则 EPS 写回内存状态覆盖磁盘文件,导致按钮重复/丢失
- 用户后续手动在"玮哥宗地v23"bar 中添加了按钮,更稳妥

## 九、技术经验与坑(复盘)

### 9.1 编码问题(踩坑最多)

| 坑 | 正确做法 |
|---|---|
| VBS 文件是 GBK 编码 | 用 GBK 读写,Python 误用 UTF-8 会损坏中文 |
| bat 中文注释乱码 | bat 必须 GBK + CRLF;纯 ASCII 内容 + ASCII 路径最稳 |
| ps1 中文乱码 | ps1 用 UTF-8 **带 BOM**(PowerShell 5.1 按 ANSI 读无 BOM 文件) |
| Python print emoji 崩溃 | 转换器脚本严禁 emoji(GBK 控制台 UnicodeEncodeError, 退出码变非0 误伤调用方) |

### 9.2 进程/环境问题

- 改 bar 文件前必须关闭 EPS(否则被写回覆盖)
- pyinstaller `--clean`/重建 build 被沙箱回收站策略拦截 → 用全新 `--workpath/--distpath` 目录绕开
- cscript / PowerShell COM 可能被安全策略拦截 → 无法脚本化验证 VBS 语法,靠人工审查

### 9.3 调用方契约

- `WScript.Shell.Run(..., 0, True)` 返回 PID 不是 ExitCode → 必须用 `Exec` + 轮询 `Status` 再读 `ExitCode`
- 调用方永远不要把"ExitCode ≠ 0"简单当成"转换失败"——先看语义(0成功 / 2 F2S防呆 / 3 S2F防呆 / 其他真错误)

### 9.4 研究结论备忘

- 加密狗作用 = 提供 4 个因子(平移+旋转),不是密码学芯片
- 空文件(无坐标)无加密标记,两狗都能打开(110.edb 实测)
- 坐标因子不在任何 ini/xml 配置中(在狗内),改配置无法让顺德狗读佛山数据
- 两狗硬件不同实锤:顺德 HardID=7308-4311-2118-7632,佛山 HardID=1364-9002-8559-3279
